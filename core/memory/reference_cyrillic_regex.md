# Reference: регулярки по кириллическому тексту

Ловушки, на которые уже наступили в Lex Digest и в «Линзе запроса» (H22).
Читать **перед** написанием любого детерминированного правила поверх русского
текста пользователя — линза, аудит, гейты.

## Почему нельзя `\w` и `\b`

`\w`, `\b` и `[[:alpha:]]` в большинстве движков (Python `re`, POSIX grep без
`-P`) привязаны к **ASCII**. По кириллице они:

- `\bслово\b` — `\b` срабатывает на каждой границе внутри кириллической строки,
  потому что движок не считает `а`..`я` «буквой слова». Границы стоят где попало.
- `\w+` — не захватывает кириллицу вообще; `\w` = `[A-Za-z0-9_]`.
- `\w`-фильтр, написанный «в общем-то правильно», на русском тексте **молча
  отбрасывает весь сигнал**. Правило компилируется, проверку проходит, в бою
  ловит ноль — и это самое опасное: нет ошибки, нет пустого результата, просто
  тишина.

В Lex так дожили до боевых данных 34 из 61 паттерна. В «Линзе» первая же
попытка посчитать висячие ссылки дала **0%** при реальных **31%** — потому что
нормализация перевела кириллицу в латиницу, а regex искал кириллицу.

## Что использовать вместо

**Множества символов с явным перечислением**, не классы:

| Не надо | Надо |
|---|---|
| `\w` | `[а-яa-z0-9_]` (с явным латинским диапазоном рядом — текст смешанный) |
| `\bслово\b` | `(?:^|[^а-яa-z0-9])слово(?:[^а-яa-z0-9]|$)` |
| `[[:alpha:]]` | `[а-яёa-z]` (после lower + ё→е можно без `ё`) |

Диапазоны указывать **оба**: `[а-яa-z]`, потому что текст пользователя смешанный
(«mvp», «репо», ссылки), и латинский диапазон нужен для тех же слов.

## Нормализация — куда переводить двойников

Буквы-двойники кириллица↔латиница (`с/s`, `о/o`, `а/a`, `е/e`, `р/p`...) —
постоянный артефакт голосового ввода и переключенной раскладки. Нормализовать
**в одну сторону** и **регулярки писать в ту же сторону**:

- пользователь диктует по-русски → правила кириллические → нормализуем **латиницу в
  кириллицу**, не наоборот.
- Инвертировав направление, можно за час получить «всё работает, но сигнал 0%»
  (см. эпиграф выше). Сторона нормализации и сторона regex должны совпадать.

Минимальный словарь двойников для русского:

```
s→с  e→е  o→о  a→а  p→р  x→х  y→у  k→к   (и заглавные)
```

Плюс `ё→е`, `Ё→Е`, `.lower()`. Этого достаточно для линзы; морфология
(склонения, беглые гласные) — **только в офлайн-аудите**, в рантайм не тянем
(`pymorphy3` тяжёлый, см. `prompt-audit.py`).

Есть ещё одна ловушка того же класса: **словарь, написанный руками рядом с
нормализацией**. Если нормализация переводит латиницу в кириллицу, то
альтернатива `stc`, набранная латиницей, после неё превращается в `сtc` и не
совпадёт никогда. Словари прогонять через ту же `normalize()` при сборке
регулярки, а не переписывать вручную (`core/scripts/lens_rules.py`).

## Кандидат ≠ баг

Любое новое правило линзы **перед включением считается по корпусу**
(`$STC_CORPUS`, по умолчанию `~/.stc/.corpus/corpus.jsonl`, собирает
`core/scripts/collect_corpus.py`): сколько реальных сообщений ловит (TP ≥ N) и
сколько ложных (FP на контроле). Не подтвердилось счётом — не включаем.
Красивая регулярка без срабатываний хуже отсутствующей: она создаёт иллюзию
покрытия. См. `prompt-audit.py` — мёртвые правила (0 срабатываний за период)
идут на удаление.

**Считать на уровне АЛЬТЕРНАТИВЫ, а не правила.** Правило NICK набирало нужные
3 срабатывания за счёт одной живой клички, а её латинские двойники внутри того
же правила были мертвы — страж этого не видел, потому что складывал всё в один
счётчик. Каждая альтернатива словаря считается отдельно (ревью 2026-07-29).

**Гейт, описанный в комментарии, не считается существующим.** У висячих ссылок в
шапке хука было написано «только первое сообщение сессии», а в коде проверялась
лишь длина запроса: из 137 срабатываний 130 приходились на середину разговора,
где подсказка «контекста нет» была ложью. Проверять гейт замером, а не чтением
комментария.

**Измеритель правила должен быть тем же кодом, что и правило.** Копия правил в
аудите (без гейтов) показывала MULTI_TASK 206 там, где хук срабатывал 69 раз, и
не могла заметить, что хук вообще сломан. Один модуль на рантайм, аудит и тест.

**Тест без данных обязан падать.** Страж корпуса при отсутствии файла печатал
«пропускаю» и выходил успешно — гарантия исчезала молча, ровно тем способом,
против которого написан весь этот файл.

**Личная копия:** в памяти воркспейса есть одноимённая заметка с историей
дефектов по проектам (Lex Digest: 34 паттерна из 61). Канон технической части —
здесь; там — проектные подробности.
