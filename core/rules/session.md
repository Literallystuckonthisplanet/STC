# Session rules

## Always-context
<!-- I01 -->

Load once: compact `behavior.md`, `pev.md`, this file, and the user profile.
Do not manually reload them. Playbook, code standard, project-doc rules,
glossary, memory index, research, and project memory are lazy by task trigger.
Each harness must use a delivery mechanism proven by a live contract test.

## Start and routing
<!-- I02 -->

- Named project/status question → central project index, then the project's
  generated `SNAPSHOT.md`; read project docs needed for the task.
- Code structure/impact → follow the snapshot's Graphify pointer.
- STC/infra question → `core/memory/SNAPSHOT.md` first, then live evidence.
- Latest weekly/monthly report has new WARN/FAIL → surface the human-named
  capability and offer a focused review; do not start a broad audit mid-task.
